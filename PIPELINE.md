# YT Search Engine — Ingestion Pipeline Reference

## YouTube Data API v3 — Rate Limits

| Resource          | Cost (units) | Daily budget (default 10 000 units) |
|-------------------|:------------:|--------------------------------------|
| `search.list`     | 100          | 100 calls/day max                   |
| `videos.list`     | 1            | 9 900 calls/day after 1 search       |
| Transcript/caption| 0            | handled by Python (unofficial)       |

**Dispatch rate:** 1 video every 2 minutes = **720 videos/day** (720 units consumed)
Override via `app.youtube.dispatch-interval-ms` in `application.yml`.

## Database Tables Involved

### `indexing_jobs` — work queue
| Column            | Type          | Notes                                            |
|-------------------|---------------|--------------------------------------------------|
| `id`              | BIGSERIAL PK  |                                                  |
| `video_id`        | INTEGER FK    | `videos.id` — NULL before video row exists       |
| `youtube_video_id`| VARCHAR(20)   | always present; key used by Kafka events         |
| `channel_id`      | INTEGER FK    | `channels.id`                                    |
| `industry_id`     | INTEGER FK    | `industries.id`                                  |
| `status`          | VARCHAR(20)   | `pending` → `processing` → `done` / `failed` / `skipped` |
| `priority`        | SMALLINT      | 1–10, higher = dispatched first                  |
| `attempts`        | SMALLINT      | incremented on each claim                        |
| `max_attempts`    | SMALLINT      | default 3                                        |
| `error_message`   | TEXT          | set on failure                                   |
| `queued_by`       | VARCHAR(50)   | Kafka topic or cron name that created the job    |

Index: `idx_jobs_queue ON (status, priority, created_at) WHERE status IN ('pending','failed')`

---

### `transcripts` — one row per video/language/source
| Column             | Type        | Notes                                         |
|--------------------|-------------|-----------------------------------------------|
| `id`               | SERIAL PK   |                                               |
| `video_id`         | INTEGER FK  | NOT NULL                                      |
| `language_id`      | INTEGER FK  | NOT NULL                                      |
| `source`           | VARCHAR(20) | `youtube_auto`, `youtube_manual`, `whisper`   |
| `full_text`        | TEXT        | complete raw transcript                       |
| `confidence_score` | NUMERIC     |                                               |
| `is_primary`       | BOOLEAN     | main transcript for this video                |

UNIQUE `(video_id, language_id, source)`

---

### `transcript_chunks` — core search table
| Column         | Type           | Notes                                              |
|----------------|----------------|----------------------------------------------------|
| `id`           | BIGSERIAL PK   |                                                    |
| `transcript_id`| INTEGER FK     | NOT NULL — must exist before inserting             |
| `video_id`     | INTEGER FK     | NOT NULL — denormalised for search performance     |
| `chunk_index`  | INTEGER        | 0-based position within transcript                |
| `text`         | TEXT           | NOT NULL — ~30 sec window                         |
| `start_time`   | NUMERIC(10,3)  | NOT NULL — seconds from video start               |
| `end_time`     | NUMERIC(10,3)  | NOT NULL                                           |
| `prev_text`    | TEXT           | 5-sec overlap from previous chunk                 |
| `next_text`    | TEXT           | 5-sec overlap into next chunk                     |
| `embedding`    | vector(384)    | NOT NULL — generated by Python embedding service  |

Indexes: HNSW on `embedding`, GIN on `to_tsvector(text)`, btree on `video_id`

> **Java cannot insert into this table directly.**
> `transcript_id` (FK) and `embedding` (vector, NOT NULL) require Python.

## Full Pipeline Flow

```
POST /api/ingestion/discover?query=X          (Admin only)
  └─ YouTubeDiscoveryService.discover()
       ├─ YouTubeQuotaGuard.tryConsume(100)   ← deduct search.list cost
       ├─ YouTubeSearchClient.searchVideos()  ← YouTube Data API v3
       ├─ filter already-indexed videos
       └─ VideoIngestionQueue.enqueue(videoIds)   ← Redis LIST

Every 2 minutes — VideoDispatchScheduler.dispatch()
  ├─ 1. IndexingJobRepository.claimNext()
  │       SELECT … FOR UPDATE SKIP LOCKED
  │       UPDATE indexing_jobs SET status='processing', attempts++
  │       → publishes video.index.request (Kafka)
  │
  └─ 2. fallback: VideoIngestionQueue.dequeue()   ← Redis
         → publishes video.index.request (Kafka)

Python worker consumes video.index.request:
  ├─ Fetch YouTube transcript (youtube_transcript_api)
  ├─ Chunk into ~30-sec windows with 5-sec overlap
  ├─ Embed each chunk (bge-small-en-v1.5 via SentenceTransformers)
  ├─ INSERT transcripts (one row)
  ├─ INSERT transcript_chunks (N rows, with embedding)
  ├─ UPDATE videos SET embedding = avg(chunk embeddings),
  │                    indexing_status = 'processing'
  └─ Publishes video.index.complete (Kafka)

IndexingEventConsumer.onIndexComplete():
  ├─ IndexingJobRepository.markDone(youtubeVideoId)
  │     UPDATE indexing_jobs SET status='done'
  ├─ UPDATE videos SET indexing_status='indexed', indexed_at=NOW()
  └─ cacheManager.getCache("search").clear()
```

## Java Ingestion Classes

| Class | Package | Role |
|-------|---------|------|
| `YouTubeQuotaGuard` | `ingestion` | Redis atomic daily quota (Lua script, StringRedisTemplate) |
| `VideoIngestionQueue` | `ingestion` | Redis LIST FIFO queue for ad-hoc video IDs |
| `YouTubeSearchClient` | `ingestion` | YouTube Data API v3 `search.list` via RestClient |
| `YouTubeDiscoveryService` | `ingestion` | Orchestrates search → filter → enqueue |
| `IndexingJobRepository` | `ingestion` | JDBC on `indexing_jobs`: claimNext, markDone, markFailed |
| `VideoDispatchScheduler` | `ingestion` | `@Scheduled` every 2 min, drains both queues |
| `IngestionController` | `ingestion` | `POST /discover`, `GET /status` (ADMIN only) |
| `IndexingEventConsumer` | `kafka/consumer` | `video.index.complete` → markDone + video indexed |
| `TranscriptChunkRepository` | `common/repository` | Read-only: countByVideoId, isIndexed |

## Admin API Endpoints

### `POST /api/ingestion/discover?query=<text>`
Triggers YouTube search and enqueues discovered video IDs.

**Response:**
```json
{
  "query": "machine learning",
  "enqueued": 42,
  "redisQueueSize": 42,
  "quotaRemaining": 9900
}
```

### `GET /api/ingestion/status`
Pipeline health snapshot.

**Response:**
```json
{
  "jobsPending": 120,
  "jobsProcessing": 1,
  "jobsDone": 598,
  "jobsFailed": 3,
  "redisQueueSize": 0,
  "quotaRemaining": 9280
}
```
