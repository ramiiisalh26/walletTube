Core Concepts

YouTube API

yt_category_id

YouTube's own numeric label assigned to every video (e.g. "28" = Science & Technology, "27" = Education). Only available via the YouTube Data API — never from the DOM or the extension.

Classifier

industry

Your own classification slug (programming, education, business, creative, fitness). Derived by VideoClassifier using 4 cascading levels. Never comes directly from YouTube.

Multiple Sources

channel

The YouTube channel entity (name, real ID, subscribers). Extension creates a placeholder row from the DOM. Crawler populates the real row from the YouTube API with full metadata and is_monitored=true.

VideoClassifier — 4-level cascade

Level Method Input needed Accuracy Coverage Available in extension?
1 Channel inheritance channel.primary_industry_id 95% ~80% of videos ✅ yes — if channel was previously classified
2 YouTube categoryId map yt_category_id 70% ~15% of videos ❌ no — categoryId not available from DOM
3 Keyword matching title + description text 60% ~4% of videos ✅ yes — title from DOM, description empty
4 Embedding cosine similarity title+description vector + industry vectors from DB 80% fallback ✅ yes — uses gRPC embedding client

End-to-end data flow

THREE PATHS THAT WRITE video + channel ROWS PATH A — Chrome Extension (user opens a YouTube video) DOM: title, channel_name ↓ GET /api/video/{yt_id}/index/stream?title=...&channel=... ↓ video.py: Channel row → find by name OR create with fake youtube_channel_id "ext_..." Video row → title (DOM), thumbnail_url (deterministic), is_monitored=False classify → Level 1 (channel) → Level 3 (keyword) → Level 4 (gRPC embed) transcript → fetch_transcript(fast=True) chunks → chunk + embed via gRPC → insert transcript_chunks UPDATE videos SET indexing_status='indexed', embedding=mean(chunks) PATH B — Scheduler + Pipeline (Celery / run_indexing.py) IndexingJob row exists (put there by fetch_trending / scan_channels) ↓ IndexingPipeline.run(job): Video row → YouTube API _enrich_video_metadata(): title, description, thumbnail_url, duration_seconds, view_count, tags, yt_category_id, published_at classify → Level 1 → Level 2 (categoryId) → Level 3 → Level 4 transcript → fetch_transcript() chunks → chunk + embed via LOCAL EmbeddingModel → insert transcript_chunks UPDATE videos SET indexing_status='indexed', embedding=mean(chunks) PATH C — Crawler only (no indexing, just channel/video discovery) Scheduler: discover_channels (daily midnight) YouTube search().list(type=channel) → channel IDs get_channel_meta() → name, description, thumbnail_url, subscriber_count INSERT channels (is_monitored=True, subscriber_count >= 10,000) Scheduler: scan_monitored_channels (every 6 hours) SELECT channels WHERE is_monitored=True get_channel_video_ids(since=last_crawled_at) INSERT IndexingJob (channel_id, industry_id from channel, priority=7) ← Jobs are then processed by PATH B (drain_queue every 5 min)

Known gaps — extension vs pipeline

⚠️ Extension channel rows are placeholders The extension creates a channels row with a fake youtube_channel_id (ext_dQw4w9WgXc). If the crawler later discovers the same real channel, it creates a second row with the real ID. The video's channel_id stays pointing at the fake row — they are never merged. This means scan_monitored_channels will never pick up these channels for future video discovery.
